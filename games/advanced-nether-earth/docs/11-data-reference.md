# 11. Data reference

Every data entry of the game in play, in address order and grouped by module, with the routines that read and write it in recording `r2` (from `GameEntry`, frame 4753, to its end: the game menu, play, a save, two loads). Generated by `python3 tools/fig_dataref.py`; do not edit by hand.

- **Entries**: src/game/game.ann. Each runs to the next entry; a variable past the image has the size its annotation gives.
- **Read by / Written by**: the routines of `r2` whose L1 profile (`work/stage3/r2/l1.json`) reads or writes a byte of the entry in its bank. "none seen" means `r2` did not touch it in play; it is not a claim that nothing does. Routines in another bank are named by bank and address; `$4000`-range addresses are the disk module's copy.
- **Left out**: the IM 2 vector fetch. Pentagon's data bus reads `$FF` during the acknowledge, so every interrupt reads `$68FF-$6900` of `ImTable`; L1 counts that read to the interrupted routine. Also left out: the boot's code before `GameEntry` (the depacker that writes the whole image).
- **The other banks** (1, 3, 4, 6, 7) are listed last as regions; their parts' own entries come with their modules (doc 02, 2.6).
